# 已批准 PPT 视觉稿：逐页拆分与重组

适用：用户已认可完整视觉图，想按游戏 UI 资产的思路拆出可复用素材，并保留正文可编辑性。

## 批准门槛

- 区分视觉稿批准与切图批准。用户要求逐页确认时，仅做当前页，完成并展示后等待批准，再处理下一页。
- 切图节奏采用用户最新指令：“一张一张、同意再下一张”则逐页停等；用户后来明确无需批准、拆完继续时，就按页序连续做完，不额外暂停。最新指令覆盖旧节奏偏好。
- 不因切图任务就重新设计已批准内容。先验证当前页，再把实证经验写入 skill，不把单次参数当普适真理。

## 先分类再切

| 对象 | 处理方式 |
|---|---|
| 证书、成绩单、实习证明、原始截图 | 复用项目中的原文件，保留比例与内部字迹，不让生成模型重绘 |
| 普通标题、正文、图注、数据 | 独立原生文本/表格/图表，OCR仅辅助定位和校对，不作为事实来源 |
| 书法或立体大标题 | 可保留原像素图片层，明确不能直接改字；不同时叠加可见同文文本 |
| 人物 | 原像素抠图优先；头发、眼镜、深色衣服和复杂蓝背景不能仅凭亮度去背 |
| 斜带、装饰、图标 | 按逻辑对象拆分，透明PNG保留轮廓、发光留量；框架与文字分开 |
| 背景 | 去除前景后补全，被遮挡部分是重建，不宣称恢复原始设计文件 |

整体背景无需透明。前景PNG须检查真实alpha，不以图片查看器显示的RGB当成透明效果。真实证据图片内部白底属于材料本身，不随意删除。

## 单页处理顺序

1. 读取源图实际尺寸，记录元素坐标、比例、层序、来源与处理方式；在叠加图验证边界。
2. 先试一个有代表性的对象。纯色底可去背；复杂渐变/建筑背景不要直接全页debg。人物用语义分割或受控蒙版，保留人脸原像素。
3. 获取无字无前景底图，或可靠的局部清理层。普通文本烧录残影必须去净；不能只用新字盖旧字。
4. 导出命名PNG与manifest。书法按实际行/词分件；普通文字单列文案与坐标，供原生重组。
5. 原位重组，检查位置、层序、字形、边缘、人物与弧带遮挡关系。不要把仍带字的容器切件与同文文本框叠放。
6. 在棋盘格、深底、浅底查看透明素材；检查人物蓝边、漏字、裁断光效、半透明发灰。再看全尺寸原位预览。
7. 交付当前页切件、manifest和重组检查图；若当前交付范围含PPT，则另交原生重组页并检查对象与文字可编辑性。是否等待批准遵从用户最新明确要求；已取消逐页批准则继续下一页。

## 完整单元素提取流程（游戏UI式视觉稿）

这里的“逐元素”是先按视觉语义确定一个对象，再把对象制成独立素材；不是把整页交给连通域算法猜测语义。每页按以下顺序复现：

### 1. 锁定源稿与对象清单

- 复制并只读保留获批视觉稿；检查原始PPT/合成脚本、源图片、字体与证据材料，优先回到真正的源资产。
- 逐页登记对象：底图、人物、书法标题、普通文字、按钮/面板/横幅、图标/插画、证书或截图。给每件确定唯一名称、源坐标、目标坐标、层级、来源和可编辑方式。
- 坐标先从合成脚本/manifest读取；没有源坐标时，在原图上标注并输出坐标叠加预览，请求人工核验边界后再切。禁止凭缩略图目测切割线。

### 2. 按对象类型提取

| 对象 | 实际做法 | 质量边界 |
|---|---|---|
| 原始证书、照片、截图 | 从原路径复制原文件；记录来源和SHA-256；按比例放入PPT | 不重绘、不去掉证书纸面、不改内部字迹 |
| 普通文字 | 采用已核验的原文与坐标，重建为独立原生文本框 | OCR只帮找位置/校字，不作为经历、奖项、数值的事实来源 |
| 书法/发光标题 | 按每行或词组框选原稿像素；按实际字色/亮度做受控alpha蒙版，必要时闭运算、羽化；在棋盘格和深浅底检查 | 不同颜色的字分别验证；不得用单一阈值损伤白色高光。不能干净提取时，保留为单件图或按批准风格重建，并标注不可逐字编辑 |
| 人物 | 优先使用独立原照；按人工标出的轮廓提供确定/可能前景背景种子，用 GrabCut 或受控分割；必要时头发、衣服、底边分区修边 | 保留原人像像素；不可只用蓝/白颜色阈值粗暴去背；特别检查发丝、眼镜、衣服孔洞和原有前景遮挡 |
| 图标、插画 | 优先复用源图层；否则按源坐标裁单件并制作蒙版。若是整体插画，允许它作为一个语义完整的单件，不必拆成无意义碎片 | 真实透明alpha；保留光晕/投影边缘，避免切断相互遮挡关系 |
| 按钮、面板、横幅 | 优先复用源素材；无源资产时可生成无字组件展板，只含装饰容器，不含证书、人物和正文。按展板坐标单件裁出；适配尺寸时可用九宫格，仅拉伸中间区域、保留边角 | 组件展板的坐标与原幻灯片坐标分开记录；检查边框、斜角不变形且留出文字安全区 |
| 背景 | 复用原背景，或在删除前景后做局部修复/按批准稿重建 | 生成式填补/修复是重建背景，不得称为恢复源设计；检查原元素残影与修补接缝 |

### 3. 用算法裁切，但不把裁切算法当作语义识别

- `detect`：仅在对象已由透明蒙版隔离、且各组件之间透明分开后，用连通区域标记批量裁出alpha边界；若组件相接会粘连，先修改蒙版或逐件按坐标导出。
- `grid` / `grid-detect`：仅用于规则雪碧图/组件展板且已确认格数，不用于整页PPT。
- `debg`：仅用于边缘连通的近似纯色背景；渐变、照片、发光与渐变边缘不直接整页去背。
- 本项目获批PPT实战采用的是“脚本/manifest坐标 + PIL/OpenCV逐对象裁切和蒙版 + 原件复制 + 空白组件展板/九宫格适配”，并非 `detect` 对整页一键自动语义分割。算法可替代重复的边界裁切步骤，不能替代逐件判断。

### 4. Manifest驱动重组

每页manifest至少包含：`page`、`source`、画布尺寸、背景来源、每个素材的语义名称、文件路径、源坐标（如有）、幻灯片坐标、对象类型、真实alpha状态、证据原件来源/哈希、适配方法、图层顺序、普通文本内容/坐标/字体/字号/颜色及已知限制。用manifest程序化组装PPT：背景在底、装饰容器在下、人物/证据/插画按遮挡关系排列，原生文本在对应层级。对象使用有意义的选择窗格名称。

### 5. 必做验收与停止条件

1. 棋盘格、深底、浅底查看单件；确认alpha不是仅有透明外观、没有背景色块、漏边、白边、粘连、裁断或字色误删。
2. 按manifest原坐标重组，与获批视觉稿并排/叠加检查位置比例、层序、遮挡、文字换行。重建背景允许局部视觉差异，但要标清。
3. 试移/隐藏代表性的面板、人物、证书：被移走的对象不能在底图上留重影，其他对象不能因此缺损。证书仍是独立的原始图片对象。
4. 检查PPT对象计数、选择窗格名称、文字可编辑性、素材链接/嵌入、画布边界和重新打开/导入；保存每页预览、manifest、验证结果。
5. 如仍只是整页截图、固定格子裁片、对象带原底色块或移除后有残影，判定未完成；继续修复或明确限制，不得按“像素可拼回”验收。

某页边界不可靠时先停在该页修蒙版/回查原件，不要把失败切件继续批量套到后续页。项目若已授权连续切图，修复后按页序继续，不另设批准暂停。

## 可靠性边界

- 裁框不等于抠图；矩形PNG带原背景时明确标为不透明块，不冒充透明单件。
- 在图层可移动的交付中，不能用“原位遮住了”掩盖底层残影或大块修补伪影。
- 不为凑全可编辑而破坏书法外观，明确哪些是图片、哪些是真文本。
- 不硬编码个人代理、学校、赛道、届次、页数等到通用工作流，读取当前项目约束。
- 联网操作遵守使用者项目的代理设置；内置搜索/生图服务不能声称受本机代理控制。
- 写新版本或精确替换本轮产物，保留批准原图；禁止为避免旧文件混计而清空整个素材目录。

## 整页视觉稿的组件展板路线

当用户要求游戏UI式组件拆分时：先按已批准页提取组件清单及原位坐标，再参照该页风格生成一张无字平铺组件展板；组件之间留足间隔，使用透明或可分离纯色底。按逻辑对象逐件裁出并验证真实alpha，再按原布局回贴。展板位置不是原PPT位置，必须单独保存atlas_box和slide_box，不把展板行列位置直接当作落位坐标。

- 先查生成/合成脚本和原始素材。已经本地拼入的证书、成绩单、截图直接复用原文件，不能因为最终页是PNG就称无原件或交付网格裁片。
- 人物使用原件或经过检查的原像素透明人物层；证书白纸属于证书内容，保留不去除。
- 展板仅生成装饰容器、斜带、图标和框架，不生成证书、人像或证明内容，不包含普通正文。普通文字用原生文本框重建。
- 装饰背景与组件可再生成，但要标明按参考重建，不能声称恢复了原始隐藏图层。艺术字可沿用批准稿像素层。
- **验收约束：整页机械网格切片即使能够按像素拼回，也不等于独立元素拆分或可编辑交付。不得以网格裁片、像素还原或对象数量作为语义拆件完成的替代证明。**
- 验收：在PPT中移走一个信息面板或证书后，其他对象完整且底层无重复残影；普通文字可直接修改；透明件无粘连和裁断。先验证代表页再写回技能中的可用经验。
- 展板不是必须步骤。用户要求沿用已验证的封面方法时，以最终独立层效果为准，选择原像素蒙版、原件复用或空组件重建；不要为了固定流程重新生成已有可用素材。
- 面板适配可保留斜角/边框并伸缩中部；源组件透明外边距过大时先检查有效轮廓再适配，否则边框可能压到正文。书法的金色与青白色高光应分别检查，不能用只保留暖色的阈值误删白字。
- 验证导出的PowerPoint选择窗格名称，不仅检查代码中的name参数；必要时给实际cNvPr命名，确保图片和文本对象能被用户识别。

## 本次封面验证所得

- 图片查看器可能显示透明区保留的RGB，必须用真实alpha合成棋盘格检查，不能仅看原PNG预览判断透明度。
- 深蓝背景、头发、西装不能用同一蓝色阈值区分。人物蒙版在头部与衣服处需要不同约束；先检查蓝背景残留，再检查头发被误删与衣服透明洞。
- 人物与前景弧带有遮挡关系，先记录原位交界；只看单件透明图合格不足以证明原位重组无缺口。
- 字体、字号与旋转需在最终渲染中复查，避免普通文字重建后换行、斜带文字角度错误。
